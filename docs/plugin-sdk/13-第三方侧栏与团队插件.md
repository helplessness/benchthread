# 在二级侧栏发布自己的面板和 Agent 团队

[React / Vue 侧栏前端 SDK、本地调试与导入示例](../../packages/tcode-panel-sdk/README.md)

下载[文献证据助手安装包](../../examples/plugins/文献证据助手.zip)与[两页示例 PDF](../../examples/plugins/证据核对示例.pdf)。在桌面端创建任务并选择工作区，打开 **扩展 → 插件 → 安装插件**，选择 ZIP 并提交。安装成功后点击 **加载已安装插件**，检查申请的权限，点击 **同意并加载**。插件出现在扩展的二级侧栏。侧栏跟随当前会话已确认的模型。用户切换后即可在面板提问，插件无需单独选模型或配置 API Key。

打开文献证据助手，选择示例 PDF，输入“请分别给出两组阅读任务的完成情况和研究设计局限，各引用一条原文”。两张证据卡应分别引用第 1 页的完成数和第 2 页的分组局限。点击某张卡的“核对这一条”，复核结果出现在该卡下。“带入对话”将选中证据和已授权的原 PDF 放进主会话草稿，用户可补充问题再发送。附件会在当前工作区获得独立路径。

插件详情提供权限开关。比如关闭文档读取后，新的 PDF 读取请求会被拒绝。点击 **卸载** 停止加载。点击 **删除插件** 并确认可撤销 ZIP 安装登记并移除安装文件。结果摘要保存在工作区的 `download/plugin-results/`，已分享文档保存在 `upload/plugin-evidence/`。

## 开发与打包

1. 将[完整示例源码](../../examples/plugins/evidence-assistant/plugin.json)复制到开发工作区。纯面板插件可以省略 `agents` 和面板的 `agent`，纯团队插件可以省略 `panels`。声明式插件使用 `runtime: "declarative"`，无需 Python 入口。已有 Python 扩展仍使用原有 SDK。
2. 面板声明 `id`、`title`、包内相对 HTML 路径 `entry`，按需指定团队入口 `agent` 和 `capabilities`。将前端构建为自包含 HTML，内联脚本与样式。宿主提供隔离 iframe 及版本化消息接口，面板无需知道本机服务端口或凭据。
3. 把角色写入 `agents` 声明的 JSON 文件或目录。社区声明式角色名使用插件名转下划线后的前缀，例如 `evidence_assistant_reader`。角色可声明中文显示名、说明、内联提示词、隐藏状态。协调者通过 `members` 引用同包的叶子角色。面板运行时依次调用成员，协调者结合成员输出回答，所有角色使用当前模型。此入口执行受限的模型任务；已有 Python 工具、异步 MCP 和 Workflow 继续按各自的宿主机制声明。
4. 打开 **扩展 → 插件 → 安装插件 → 从本地开发目录导入**，输入相对于当前工作区的目录，登记并加载。修改团队定义后卸载再加载。交付时使用 SDK 生成带文件清单的 ZIP。以下命令在仓库根目录执行。

```bash
python scripts/plugin.py validate examples/plugins/evidence-assistant
python scripts/plugin.py test examples/plugins/evidence-assistant
python scripts/plugin.py pack examples/plugins/evidence-assistant --output /tmp/evidence-assistant.zip
```

## 面板 SDK v1

iframe 中可以直接访问 `window.tcodePanel`。每个请求都与当前面板、工作区、会话和 harness 绑定。JavaScript 通信契约和 TypeScript 声明随仓库发布。[SDK 源码](../../packages/tcode-panel-sdk/index.js) · [类型声明](../../packages/tcode-panel-sdk/index.d.ts)

| 方法 | 输入与结果 |
|---|---|
| `submit(turn)` | 首次提交传入唯一 UUID、问题，以及可选的文件名和 PDF 的 Base64 内容。返回独立运行 ID。对同一提交重试时复用 UUID；相同 UUID 与不同输入会被拒绝。 |
| `history()` | 返回当前面板在本会话的最近 32 次运行及当前授权。运行状态包括执行中、完成、失败、中断和取消。应在打开面板时读取，并在有运行中的任务时刷新。 |
| `submit({request_id, question, source_run, item_id, selection})` | 对已有结果继续提问。传入来源运行 ID、稳定条目标识和选中内容，宿主按原运行读取文档。插件负责渲染条目及复核结果。 |
| `share({run, item_id, text})` | 由用户明确选择的操作触发。检查分享权限，将条目和来源写入当前对话草稿。仍有文件读取权限时附上原 PDF。 |
| `cancel(run)` | 停止指定面板运行，其他运行和主聊天独立。关闭面板、刷新、切换 harness 可以继续跟踪原任务。 |

文献示例申请三个范围：`document.read` 读取用户主动选择的文件，`team.run` 调用本包团队，`selection.share` 将选中内容带入对话。用户可在插件列表更改授权。Python 工具权限继续使用清单中的具体范围和目标模式。切到外部 harness 后，当前会话的 TCode 插件入口和面板调用停用；切回 TCode 后恢复历史。宿主服务重启时，中途退出的本地模型任务会标记中断。

## 桌面复测

[桌面端到端用例](../../desktop/test/acceptance/plugin_panel.py)通过 Chromium 调试口操作运行中的 Electron 窗口。请使用独立桌面测试实例，配置可用的聊天模型与 OpenCode。脚本创建一次性工作区，选择本地 ZIP，实际调用模型并执行卸载与删除。需要 Python Playwright，结束后可以保留工作区核对历史记录。
